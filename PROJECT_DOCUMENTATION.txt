1.1  WHAT IS THIS PROJECT?
---------------------------
Name        : EJ-SSPI SIMULATOR
Full Form   : Electronics & Junior - Single Stage Power Amplifier / Signal Processing Interactive Simulator
Target User : MSBTE Electronics Engineering Students (K-Scheme syllabus)
Purpose     : A website (runs in a browser) that lets students:
              - BUILD digital logic circuits by dragging and dropping components
              - SIMULATE how electricity flows through those circuits in real-time
              - LEARN analog electronics (amplifiers, power circuits, oscilloscopes)
              - STUDY exam notes with quizzes, flashcards, and AI tutor help

Think of it like a 'virtual electronics lab' - students don't need actual hardware;
they can do all their MSBTE practicals on a computer or phone.

1.2  WHAT DOES THIS APP DO?
----------------------------
The app has FOUR main sections:

  [A] CIRCUIT SIMULATOR (Digital)
      - Drag components (AND/OR/NOT gate, flip-flops, etc.) onto a canvas (drawing board)
      - Connect them with wires
      - Click Run to see signals flow (1s and 0s) in real time
      - View truth tables, waveforms, and oscilloscope output

  [B] ANALOG ELECTRONICS LAB (MSBTE Practical Lab)
      - Simulates Practical No. 1: Class A Power Amplifier (SL100 NPN transistor circuit)
      - Animated circuit diagram showing current flow through components
      - Live calculations: Voltage Gain, Efficiency, Ic, Ib, Ie currents
      - Power Electronics practicals (rectifiers, Zener regulators, converters)

  [C] EXAM NOTES
      - Full subject notes: Digital Technique (22317) and Analog Electronics (22320)
      - Flashcards, micro-quizzes, memory tricks, real-life examples
      - Interactive step-by-step problem solving
      - AI Tutor Bot that answers student questions

  [D] PRACTICE SECTION
      - Question bank with multiple-choice and numerical problems
      - Immediate answer checking with full explanation

1.4  LIBRARIES AND TOOLS USED
--------------------------------

  [A] MAIN DEPENDENCIES - These run inside the final app:

  react (v19.2.7)
    The most popular JavaScript UI library. Builds the app as 'components'
    (reusable UI pieces). Like LEGO blocks - Navbar, Canvas, Modal are all
    separate React components. When data changes, only affected parts redraw.
    Functions used: useState, useEffect, useRef, useCallback, React.FC

  react-dom (v19.2.7)
    Works with React to physically show components inside the browser HTML.
    Main function: ReactDOM.createRoot().render() in main.tsx.
    Connects React's virtual world to the real browser webpage.

    Used as React components: <Play />, <Trash2 />, <ZoomIn />, etc.

    Creates a colorful confetti celebration animation in the browser.

    The build tool. Compiles all TypeScript/TSX files into browser-readable

  typescript (v6.0.2)
    Adds type safety to JavaScript. tsc (TypeScript Compiler) checks code

    A very fast JavaScript/TypeScript code quality checker (linter).

1.5  HOW THE PROJECT IS RUN
-----------------------------

  DEVELOPMENT (Testing while building):
    > npm run dev
    Starts the Vite development server. App opens at http://localhost:5173
    Any code changes appear instantly without needing to refresh (HMR).

  BUILD (Creating final files for deployment/hosting):
    > npm run build
    Creates optimized, compressed files in the /dist folder for web hosting.

  TYPE CHECK (Checking for TypeScript errors):
    > npx tsc --noEmit
    Scans all TypeScript files for type errors. Does not produce any output files.

  LINT (Code quality check):
    > npm run lint
    Runs oxlint to find code quality problems and style issues.

3.3  src/App.tsx  (Size: ~46 KB - largest logic file)
--------------------------------------------------------
The ROOT COMPONENT - the 'command center' of the entire application.
Manages all shared state that multiple child components need.

  State managed by App.tsx:
  CIRCUIT STATE:
  - nodes[]           : Array of all components placed on the canvas
  - wires[]           : Array of all wire connections between components
  - selectedNodeIds[] : Currently selected component(s)
  - clipboard[]       : Copy-pasted components buffer
  - history[]         : Undo/Redo stack of circuit snapshots

  UI STATE:
  - activeTab         : Which section is currently shown (simulator/exam notes)
  - isRunning         : Whether the circuit simulation is running
  - theme             : 'dark' or 'light' mode
  - zoom, pan         : Canvas viewport zoom level and pan position
  - clockSpeed        : Simulation speed in Hz

  Key functions:
  - handleAddNode()      : Adds new component to canvas
  - handleDeleteNodes()  : Removes selected components
  - handleAddWire()      : Creates wire connection between ports
  - handleUndo/Redo()    : Navigate undo/redo history stack
  - handleExportJson()   : Save circuit to .json file
  - handleImportJson()   : Load circuit from .json file
  - handleExportPng()    : Save canvas as PNG image

  Simulation Loop (heart of the simulator):
  Uses setInterval() to run repeatedly every (1000/clockSpeed) ms.
  Each tick: tickClockNodes() -> propagateCircuit() -> setNodes/setWires
  This makes signals appear to 'flow' in real time on the canvas.

3.6  src/engine/GateLogic.ts  (Size: 37 KB - most complex engine file)
-----------------------------------------------------------------------
THE CORE LOGIC ENGINE. Defines ALL 60+ components and their behavior.

  COMPONENT_METADATA[] array:
  Lists all 60+ components with display info used by the Palette:
  { type, label, category, description, defaultWidth, defaultHeight, iconName }

  createDefaultPortsForNode(type, nodeId):
  Creates the correct Port objects for each component type.
  AND gate -> 2 input ports + 1 output port
  JK Flip-Flop -> J, K, CLK inputs + Q, NOT-Q outputs

  evaluateNodeLogic(node) - THE MOST IMPORTANT FUNCTION:
  Takes a CircuitNode and returns its output based on current inputs.

  Logic rules for each gate:
  AND gate:      Output=1 ONLY if ALL inputs are 1. Otherwise 0.
  OR gate:       Output=1 if ANY input is 1.
  NOT gate:      Output=opposite of input (0->1, 1->0)
  NAND gate:     Output=NOT(AND) - opposite of AND gate output
  XOR gate:      Output=1 ONLY if inputs are DIFFERENT
  XNOR gate:     Output=1 ONLY if inputs are SAME
  Half Adder:    SUM=A XOR B, CARRY=A AND B
  Full Adder:    SUM=A XOR B XOR Cin, COUT=(A AND B) OR (Cin AND (A XOR B))
  D Flip-Flop:   Q changes to D value only on rising clock edge
  JK Flip-Flop:  J=1,K=0->Set | J=0,K=1->Reset | J=1,K=1->Toggle
  T Flip-Flop:   T=1->Toggle Q on clock | T=0->Hold Q
  SR Latch:      S=1->Set Q=1 | R=1->Reset Q=0 | S=R=0->Hold | S=R=1->Invalid
  MUX 2:1:       SEL=0->output=I0 | SEL=1->output=I1
  DEMUX 1:2:     SEL=0->data goes to O0 | SEL=1->data goes to O1
  Counter 4-bit: Counts 0->15 in binary, wraps to 0 on overflow
  Decoder 2:4:   Activates one of 4 outputs based on 2-bit input
  Timer 555:     Generates square wave using RC timing formula
  NPN BJT:       If Base=HIGH, Collector-Emitter conducts (ON)

3.7  src/engine/CircuitEvaluator.ts  (Size: 4.5 KB)
----------------------------------------------------
Runs the SIMULATION - makes signals flow through the entire circuit.

  propagateCircuit(nodes[], wires[]) function:
  Algorithm: Fixed-Point Iteration (max 15 passes):
    Pass 1: For each wire -> read source output port -> write to wire -> write to target input
    Pass 2: For each node -> call evaluateNodeLogic() -> update output port values
    Repeat until NOTHING changes OR 15 iterations done (prevents infinite loops)

  Why iterate multiple times?
  Feedback circuits (e.g., SR latch) need multiple passes to reach stable state.

  tickClockNodes(nodes[]) function:
  Flips state (0->1 or 1->0) of all CLOCK, AC_SUPPLY, FUNCTION_GEN, SINE_GEN nodes.
  Called before propagateCircuit() on every simulation timer tick.

3.8  src/engine/TruthTable.ts  (Size: 3.8 KB)
----------------------------------------------
Generates a TRUTH TABLE for any gate automatically.

  getBooleanExpression(type, inputNames[]):
  Returns Boolean algebra expression as text:
  AND (A, B)   -> 'Y = A . B'
  OR  (A, B)   -> 'Y = A + B'
  NOT (A)      -> 'Y = NOT A'
  XOR (A, B)   -> 'Y = A XOR B'
  Half Adder   -> 'SUM = A XOR B, COUT = A . B'

  generateTruthTableForNode(node):
  For N inputs -> generates 2^N rows (all binary combinations)
  For each row: sets dummy inputs -> calls evaluateNodeLogic() -> records output
  Marks the currently ACTIVE row (green) matching live input values

3.9  src/engine/AmplifierEngine.ts  (Size: 13.9 KB)
----------------------------------------------------
Contains PHYSICS FORMULAS for analog amplifier calculations.

  AMPLIFIER_LAB_SPECS record:
  Default parameters for each amplifier class:
  AMP_CLASS_A:  Vcc=12V, Vbias=0.7V, RL=16 Ohm, Vin=1.0V, Beta=100, f=1kHz
  AMP_CLASS_B:  Push-pull NPN+PNP, conducts 180 degrees, max efficiency 78.5%
  AMP_CLASS_AB: Reduces crossover distortion of Class B slightly
  AMP_CLASS_C:  Conducts less than 180 degrees, used in RF tuned circuits
  AMP_CLASS_D:  PWM (Pulse Width Modulation) digital switching type

  calculateAmplifierMetrics(params) uses real electronics formulas:
  Vout = Vin x Av
  Voltage Gain dB = 20 x log10(Av)
  Power Gain dB   = 10 x log10(Ap)
  Efficiency      = (Pac_out / Pdc) x 100 percent
  VCE(Q)         = DC quiescent operating voltage (Q-point)
  IC(Q)          = DC quiescent collector current
  IC(sat)        = Vcc / RL (saturation current)
  THD percent    = Total Harmonic Distortion percentage

  generateWaveformData(params, metrics):
  Creates (time, Vout) data point arrays for one complete signal cycle.
  Each class shows characteristic waveform distortion:
  Class A: Clean sine wave output (no distortion)
  Class B: Crossover distortion visible near zero crossing (0.7V dead zone)
  Class C: Only positive peak visible, rest completely clipped
  Class D: Square/PWM switching waveform output

  calculateHarmonics(type, metrics):
  Computes FFT harmonic components (fundamental + 2nd, 3rd, 4th harmonics)
  Used to display the frequency spectrum in the oscilloscope FFT view.
